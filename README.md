## 문제 정의 — 왜 건강 앱은 3일 만에 지워지는가

건강 습관 앱은 이미 많습니다. 그런데 대부분 다음 두 가지에서 같은 한계를 가집니다.

**첫째, 앱은 기록만 하고 판단은 사용자에게 떠넘깁니다.**
칼로리를 적고 체중을 적어도, "그래서 오늘 무엇을 해야 하는가"는 알려주지 않습니다.
결심이 남아 있는 이틀은 스스로 정하지만, 사흘째부터는 정할 기운이 없습니다.

**둘째, 혼자입니다.**
운동을 계속하게 만드는 힘은 정보가 아니라 사람입니다. 그런데 대부분의 앱에서 타인은
숫자로만 존재하거나(전체 랭킹), 아예 없습니다. 아무도 내가 오늘 걸었는지 모릅니다.

여기에 하나가 더 붙습니다. **"했다고 누르면 끝"이라 스스로를 속이기 쉽습니다.**
체크박스는 정직함을 요구하지 않고, 정직하지 않은 기록은 아무 변화도 만들지 못합니다.

## 해결 방식 — 두 가지를 바꿨습니다

### 1. 오늘 할 일은 AI가 정합니다

목표·성별·나이·키·몸무게에 더해 **어제까지의 기록**을 함께 넣어 오늘의 미션을 만듭니다.
사용자는 "무엇을 할까"를 고민하지 않습니다. 열면 이미 정해져 있습니다.

그리고 **지키면 어려워지고, 놓치면 쉬워집니다.**

```
달성률 90% 이상   → 난이도 상승, 미션 4개
달성률 50~90%     → 유지, 미션 3개
달성률 50% 미만   → 난이도 하향
3일 연속 실패     → 미션 1개로 축소
```

마지막 줄이 중요합니다. 대부분의 앱은 실패한 사람에게 같은 목표를 계속 들이밀고,
사용자는 "나는 안 되는 사람"이라 결론 내리고 앱을 지웁니다. WITHU는 반대로 **부담을 줄입니다.**
3일 연속 놓친 사람에게 필요한 것은 독려가 아니라 **오늘 하나는 해낼 수 있다는 경험**입니다.

### 2. 혼자 하지 않습니다

2~4인이 **같은 7일**을 함께 달립니다. 서로의 인증 사진과 달성률이 보이고,
반응과 댓글을 남길 수 있습니다.

그리고 내 캐릭터의 **표정이 내 달성률과 순위에 따라 실시간으로 바뀝니다.**
숫자로 "달성률 33%"라고 적는 대신, 내 고슴도치가 시무룩해져 있습니다.
그룹 피드를 열면 누가 잘 하고 있고 누가 힘든지가 표정만으로 한눈에 보입니다.

### 인증은 사진으로 합니다

체크박스 대신 **사진을 올리고, AI가 그 사진이 미션과 맞는지 판정합니다.**
걷기 미션에 음식 사진을 올리면 거절됩니다. 여기에 더해

- **같은 사진 재사용 차단** — 원본 SHA-256을 대조합니다
- **캡처·워터마크·화면 재촬영 판별** — 완전 방어는 불가능하지만 쉬운 우회는 막습니다

인증이 정직해야 달성률이 정직해지고, 달성률이 정직해야 **AI가 내일 미션을 제대로 조절합니다.**
세 가지가 한 고리로 묶여 있습니다.

## AI를 실제로 어디에 쓰는가

"AI를 붙였다"가 아니라 **AI가 없으면 성립하지 않는 지점**만 적었습니다.
셋 다 실제 OpenAI 호출이며, 서버 로그로 확인할 수 있습니다.

### ① 개인 맞춤 미션 생성 — 텍스트 모델

목표·신체 정보 + 지난 기록을 넣어 오늘의 미션을 만듭니다. 같은 사람이라도
어제 어떻게 했는지에 따라 오늘이 달라집니다.

**어제의 식단 분석 결과도 함께 들어갑니다.** 저녁을 계속 놓쳤다면 오늘 미션이 저녁을
정조준합니다. 기록이 다음 행동으로 이어지는 고리이고, 이 앱에서 AI가 하는 가장 중요한 일입니다.

### ② 식단 사진 분석 — Vision 모델

아침·점심·저녁 사진을 올리면 **목표에 비추어** 적합한지 판정합니다.
같은 치킨이라도 벌크업 목표와 다이어트 목표에서 다르게 읽힙니다.
이 판정 결과(내부 적합도)는 사용자에게 보여주지 않고 **다음 날 미션 생성에 들어갑니다.**

### ③ 생활습관 인증 사진 판정 — Vision 모델

"점심 후 10분 걷기"에 바깥 풍경 사진은 인정하고, 음식 사진은 거절합니다.
**거절할 때 사유를 함께 돌려줍니다** — 무엇을 다시 찍어야 하는지 알 수 없으면
사용자는 그냥 앱을 닫기 때문입니다.

실제 서버 로그입니다.

```
OpenAiMealVisionClient       인식=음식 아님 - 캐릭터 이미지   달성=false  적합도=BAD
OpenAiLifestyleVisionClient  미션=하루 30분 걷기 도전
                             인식=이미지 내용이 없음          달성=false
```

### AI가 죽어도 앱은 삽니다

해커톤에서 제공받은 키 하나로 심사 기간을 버텨야 하므로, 실패 경로를 먼저 만들었습니다.

- **한도 소진(429) 시 대체 모델로 자동 전환** — `gpt-4o-mini` → `gpt-4.1-mini` → `gpt-4.1-nano`
  (모델마다 한도가 따로 잡히므로 같은 키로 이어서 씁니다. 추가 결제가 아닙니다)
- **키가 잘못돼도** 미션은 계속 나오고, 사진 판정만 안내 문구로 대체됩니다
- **키가 아예 없으면** mock 모드로 전환되어 앱 전체가 그대로 돕니다

## 기존 웰니스 서비스와 무엇이 다른가

| | 기록형 앱 (눔·마이피트니스팔 등) | 챌린지형 앱 | **WITHU** |
|---|---|---|---|
| 오늘 할 일 | 사용자가 정함 | 운영자가 정한 고정 목표 | **AI가 매일 새로 생성** |
| 실패했을 때 | 그대로 | 그대로 (또는 탈락) | **난이도를 낮추고 개수를 줄임** |
| 인증 방식 | 직접 입력 | 체크 / 사진 업로드 | **AI가 사진을 판정 + 재사용 차단** |
| 타인의 존재 | 없음 또는 숫자 | 순위표 | **2~4인 소그룹 + 캐릭터 표정** |
| 기록의 쓰임 | 조회용 | 없음 | **다음 날 미션 생성의 입력값** |

정리하면 두 가지가 다릅니다.

**첫째, 기록이 조회용이 아니라 입력값입니다.** 오늘의 인증 결과가 내일의 미션을 바꿉니다.
사용자는 이 연결을 "어제 못 지켰더니 오늘 미션이 쉬워졌네"로 체감합니다.

**둘째, AI의 분석 결과를 숫자가 아니라 캐릭터 표정으로 보여줍니다.**
달성률 33%는 읽어야 이해되지만, 시무룩한 고슴도치는 그냥 보입니다.
소그룹 안에서 이 표정들이 나란히 놓일 때 "같이 하고 있다"는 감각이 생깁니다.

> ANIMAL LEAGUE의 동물 캐릭터 컨셉과도 맞닿아 있습니다.
> WITHU의 네 캐릭터(공룡·박새·고슴도치·박쥐)는 장식이 아니라 **AI 분석 결과를 전달하는 인터페이스**입니다.

```
                         │ https
                         ▼
        [Vercel]  React + Vite 정적 호스팅
                         │ https  (CORS: 실서비스·미리보기·localhost만 허용)

   ┌──────────────────────────────────────────────────┐
   │  가비아 클라우드 — 해커톤에서 제공받은 서버           │
   │                                                   │
   │   Caddy :443      Let's Encrypt 인증서, 자동 갱신   │
   │      │ 리버스 프록시                                │
   │   Spring Boot :8080   systemd — 죽어도 자동 재시작   │
   │      │                                             │
   │   MySQL 8 :3306   외부에 열지 않음                   │
   └──────────────────────────────────────────────────┘
                         │ https
                         ▼
                    [OpenAI API]
```

**프론트와 백엔드는 서로의 코드를 가져다 쓰지 않습니다.** 둘을 잇는 것은
`frontend`의 환경변수 `VITE_API_BASE_URL` **주소 하나**뿐이라 빌드도 배포도 따로 돕니다.

### 설계에서 신경 쓴 것 두 가지

**① 사진을 파일이 아니라 DB에 넣었습니다.**
인증 사진을 디스크에 쓰면 서버를 옮길 때 따라오지 않습니다. 해커톤 특성상 배포처가 바뀔 수
있어서(실제로 Railway → 가비아로 옮겼습니다) DB에 BLOB으로 저장하고 `/api/files/{uuid}`로
내려줍니다. 서버를 옮겨도 사진이 그대로 따라옵니다.

**② 시간대를 코드에서 한국 시간으로 고정했습니다.**
이 앱은 날짜에 크게 기댑니다 — 오늘의 미션, 미션 도착 시각, 끼니, 7일 사이클, 연속 인증.
클라우드 서버는 대부분 UTC라, 고정하지 않으면 서버를 옮기는 것만으로 "밤 10시에 한 인증이
다음 날 기록으로 저장"됩니다. 실제로 `TZ=UTC`로 띄워 재현하고 고친 뒤 다시 확인했습니다.

### 왜 API 주소가 `1-201-117-9.nip.io`인가

프론트가 https라 백엔드도 https여야 합니다 — 브라우저가 https 페이지에서 http 요청을 막습니다.
그런데 **IP만으로는 인증서를 받을 수 없고**, 대회 규정상 추가 결제 없이 가야 해서
도메인을 살 수 없었습니다.

`nip.io`는 `1-201-117-9.nip.io`를 그대로 `1.201.117.9`로 풀어주는 무료 DNS입니다.
이 이름으로 Let's Encrypt 인증서를 받았습니다. 서버 보안그룹에 80번을 열 수 없어
HTTP-01 대신 **443만 쓰는 TLS-ALPN-01** 방식으로 발급받았습니다.

## 실제로 동작한다는 근거

제출 전 배포 서버에 대고 처음부터 끝까지 직접 확인한 결과입니다.

| 확인 항목 | 결과 |
|---|---|
| 신규 가입 → 그룹 생성 → 온보딩 → AI 미션 생성 → 인증 → 랭킹·상점 | **23개 시나리오 전부 통과** |
| AI 미션 생성 | 실제 호출 확인 (목표에 맞는 문구, 응답 9초) |
| AI 사진 판정 | 실제 호출 확인 — 엉뚱한 사진을 사유와 함께 거절 |
| 같은 사진 재사용 | 차단됨 (`FILE_004`) |
| 응답 속도 (외부 HTTPS) | 0.12 ~ 0.17초 |
| HTTPS 인증서 | Let's Encrypt, 자동 갱신 |
| 서버 경고·에러 로그 | 0건 |
| 자동 복구 | 백엔드·DB·프록시 전부 부팅 시 자동 시작, 죽으면 재시작 |
| CORS | 허용되지 않은 출처는 403 |

**심사 기간 동안 데모 데이터가 스스로 유지됩니다.** 서버가 뜰 때와 **날짜가 바뀔 때마다**
데모 계정의 7일차 상태를 다시 만듭니다. 심사일이 배포일과 며칠 차이가 나도, 누군가
"계속하기"를 눌러 상태를 바꿔놓아도 원래대로 돌아옵니다. 이 과정에서 **실제 가입자의
데이터는 건드리지 않습니다.**

## 로컬에서 실행하기

**실제로 새로 clone해서 확인한 절차입니다.**

### 프론트만 띄우기 — 백엔드도 DB도 필요 없습니다

```bash
cd frontend
npm install
npm run dev
```

끝입니다. `.env`를 만들지 않으면 **mock 모드**로 동작해 로그인부터 7일 결과까지
전 화면을 그대로 볼 수 있습니다.

### 백엔드까지 띄우기

MySQL이 필요합니다. 없으면 도커로 한 줄입니다.

```bash
docker run --name withu-mysql -p 3306:3306 \
  -e MYSQL_ALLOW_EMPTY_PASSWORD=yes -e MYSQL_DATABASE=withu -d mysql:8
```

이미 MySQL이 있다면 `withu` 데이터베이스만 만들어 두세요.

```sql
CREATE DATABASE withu CHARACTER SET utf8mb4;
```

그다음 **`local` 프로필로** 실행합니다.

```bash
cd backend
SPRING_PROFILES_ACTIVE=local gradle bootRun
```

`http://localhost:8080`에서 뜹니다. 테이블은 JPA가 알아서 만듭니다.

> **`SPRING_PROFILES_ACTIVE=local`을 빼면 뜨지 않습니다.** 기본 프로필은 배포용이라
> DB 접속 정보를 환경변수에서 찾고, 없으면 `Access denied for user 'root'`로 실패합니다.
> MySQL이 3306이 아닌 포트에 있으면 `DB_PORT=3307`처럼 함께 넘기세요.

프론트를 이 백엔드에 붙이려면 `frontend/.env.local`을 만드세요.

```
VITE_API_BASE_URL=http://localhost:8080
```

### 알아두면 좋은 것

- **OpenAI 키는 없어도 됩니다.** 키가 없으면 미션 생성이 고정 문구로, 사진 판정이 통과 처리로
  대체되어 앱 전체가 그대로 돕니다. 실제 AI를 보려면 `backend/.env`에 `OPENAI_API_KEY=...`를
  넣으세요 (이 파일은 git에 올라가지 않습니다).
- **심사용 데모 데이터를 만들려면** `DEMO_SEED=true`를 함께 넘기세요.
- Gradle wrapper 다운로드가 막힌 네트워크에서는 `./gradlew` 대신 시스템 `gradle`을 쓰세요.
